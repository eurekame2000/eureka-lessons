二、前置检查（30 秒自测）

验证以下概念，如不熟悉则先补 2 分钟说明：

1. EIP-20 / ERC-20：transfer / transferFrom / approve / balanceOf 接口含义

ERC-20 是以太坊代币标准接口：

  • transfer(to, amount) — 从调用者转账给 to
  • transferFrom(from, to, amount) — 从 from 转账给 to（需先 approve）
  • approve(spender, amount) — 授权 spender 可花费调用者的 amount 代币
  • balanceOf(account) — 查询 account 的代币余额
2. ETH vs WETH：为什么需要 Wrapped Ether

原生 ETH 不是 ERC-20 代币，不能满足 transfer/approve 等接口。WETH (Wrapped Ether) 是 ETH 的 ERC-20 包装：

  • deposit() — 发送 ETH，获得等量 WETH
  • withdraw(amount) — 销毁 WETH，取回等量 ETH

DeFi 协议（Uniswap/AAVE 等）都要求 ERC-20 接口，因此 ETH 必须先 wrap 为 WETH 才能参与 AMM。

3. UniswapV2 Pair：什么是 x*y=k，为什么是恒定乘积

恒定乘积公式：reserve0 * reserve1 = k（k 不变）。

当交易者用 token0 买入 token1 时：

  • token0 储备增加，token1 储备减少
  • 由于乘积必须恒定，token1 的边际价格上升（滑点）
  • 公式保证：交易后 (reserve0 + amountIn) * (reserve1 - amountOut) >= k

这就是 AMM 的定价机制：价格由池内储备比例决定，而非订单簿。

4. 区块浏览器：你知道 etherscan.io 和如何读取 verified contract source

Etherscan 是以太坊区块链浏览器，可以：

  • 查看交易、地址、合约源码
  • 阅读已验证合约的 Solidity 源代码
  • 查看合约的读写操作（Read/Write Contract）
  • 追踪内部交易（Internal Txns）

Foundry 测试中经常需要查主网合约地址（如 USDC/WETH/Router），Etherscan 是主要数据源。

五、UniswapV2 AMM 深度速通 + 接口分析

恒定乘积公式

UniswapV2 使用 x * y = k 定价：

交易前

reserve0 = 100 ETH
reserve1 = 200000 USDC
k = 20,000,000

买入 1 ETH 后

reserve0 = 101 ETH
reserve1 = 200000 * 100 / 101 ≈ 198,019 USDC
价格 ≈ 1980 USDC/ETH

核心合约接口

// IUniswapV2Pair.sol — 交易对合约接口
interface IUniswapV2Pair {
    function getReserves() external view returns (
        uint112 reserve0, uint112 reserve1, uint32 blockTimestampLast
    );
    function swap(
        uint256 amount0Out, uint256 amount1Out,
        address to, bytes calldata data
    ) external;
    function token0() external view returns (address);
    function token1() external view returns (address);
}

// IUniswapV2Router02.sol — 路由合约接口（用户主要交互对象）
interface IUniswapV2Router02 {
    function getAmountsOut(uint256 amountIn, address[] memory path)
        external view returns (uint256[] memory amounts);

    function swapExactTokensForTokens(
        uint256 amountIn, uint256 amountOutMin,
        address[] calldata path, address to, uint256 deadline
    ) external returns (uint256[] memory amounts);

    function swapExactTokensForETH(
        uint256 amountIn, uint256 amountOutMin,
        address[] calldata path, address to, uint256 deadline
    ) external;
}

// IWETH.sol — WETH 接口
interface IWETH {
    function deposit() external payable;
    function withdraw(uint256 amount) external;
}

UniswapV2 闪电兑换 (Flash Swap)

核心特性 UniswapV2 的 flash swap 没有借贷金额上限，只要在同一个交易中 return 即可。这使它成为链上套利的理想工具：无需本金即可借出大额资产，套利后归还本息。

Flash swap 流程：

  1. 调用 pair.swap(amount0Out, amount1Out, address(this), data)
  2. Pair 合约将代币转给调用者（此时尚未检查还款）
  3. 如果 data 非空，Pair 回调 uniswapV2Call(...)
  4. 在回调中执行套利逻辑
  5. 回调结束前，必须将借出的代币 + 0.3% 手续费转回 Pair
  6. Pair 检查 reserve 是否满足恒定乘积 → 交易完成

六、三角套利合约实现

四种代币、三条路径的多跳套利：USDC → WETH → DAI → USDC

TriangularArbitrage.sol

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import "./interfaces/IUniswapV2Router02.sol";
import "./interfaces/IWETH.sol";

contract TriangularArbitrage {
    address public owner;
    IUniswapV2Router02 public router;
    IWETH public weth;

    modifier onlyOwner() {
        require(msg.sender == owner, "not owner");
        _;
    }

    constructor(address _router, address _weth) {
        owner = msg.sender;
        router = IUniswapV2Router02(_router);
        weth = IWETH(_weth);
    }

    /// @notice Execute a 3-pool triangular arbitrage
    /// @param path The swap path: [tokenIn, tokenMid, tokenOut]
    /// @param amountIn The input amount of tokenIn
    function execute(
        address[] calldata path,
        uint256 amountIn
    ) external onlyOwner returns (uint256) {
        require(path.length == 3, "need 3 tokens");

        // Step 1: Pull tokenIn from caller (must approve first)
        IERC20(path[0]).transferFrom(msg.sender, address(this), amountIn);

        // Step 2: First swap: path[0] -> path[1]
        _approveToken(path[0], amountIn);
        address[] memory path1 = new address[](2);
        path1[0] = path[0];
        path1[1] = path[1];
        uint256 midAmount = router.swapExactTokensForTokens(
            amountIn, 0, path1, address(this), block.timestamp
        )[1];

        // Step 3: Second swap: path[1] -> path[2]
        _approveToken(path[1], midAmount);
        address[] memory path2 = new address[](2);
        path2[0] = path[1];
        path2[1] = path[2];
        uint256 outputAmount = router.swapExactTokensForTokens(
            midAmount, 0, path2, address(this), block.timestamp
        )[1];

        // Step 4: Check profit
        require(outputAmount > amountIn, "no profit");

        // Step 5: Return profit to caller
        IERC20(path[2]).transfer(msg.sender, outputAmount);
        return outputAmount;
    }

    function _approveToken(address token, uint256 amount) internal {
        IERC20(token).approve(address(router), amount);
    }
}
安全问题分析
  1. 没有滑点保护：amountOutMin = 0 → 被 sandwich attack
  2. 临时资产集中在合约内：如果合约被攻击，所有资产可被抽走
  3. _approveToken 每次 approval 没有重置前值：可能导致 approval 累积问题（虽然 ERC-20 标准允许覆盖）

八、闪电贷套利合约实现

核心思路：不需要预先投入本金，从 Uniswap V2 Pair 中闪电借贷大额资产，跨 DEX 套利后归还。

FlashSwapArbitrage.sol

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import "./interfaces/IUniswapV2Pair.sol";
import "./interfaces/IUniswapV2Router02.sol";
import "./interfaces/IUniswapV2Callee.sol";
import "./interfaces/IWETH.sol";

contract FlashSwapArbitrage is IUniswapV2Callee {
    IUniswapV2Router02 public uniRouter;
    IUniswapV2Router02 public sushiRouter;
    IWETH public weth;

    constructor(address _uniRouter, address _sushiRouter, address _weth) {
        uniRouter = IUniswapV2Router02(_uniRouter);
        sushiRouter = IUniswapV2Router02(_sushiRouter);
        weth = IWETH(_weth);
    }

    /// @notice Initiate flash swap arbitrage
    /// @param pair The UniswapV2 Pair to flash loan from
    /// @param flashToken The ERC-20 token address to borrow
    /// @param flashAmount The amount to borrow
    /// @param profitToken The token to receive profit in
    function startArbitrage(
        address pair,
        address flashToken,
        uint256 flashAmount,
        address profitToken
    ) external {
        IUniswapV2Pair uniPair = IUniswapV2Pair(pair);
        (uint112 reserve0, uint112 reserve1, ) = uniPair.getReserves();
        address token0 = uniPair.token0();
        address token1 = uniPair.token1();

        (uint256 amount0Out, uint256 amount1Out) =
            flashToken == token0 ? (flashAmount, uint256(0)) : (uint256(0), flashAmount);

        // Encode profit token into callback data
        bytes memory data = abi.encode(profitToken);

        // Trigger flash swap: Uniswap will call uniswapV2Call
        uniPair.swap(amount0Out, amount1Out, address(this), data);
    }

    /// @notice UniswapV2 callback — execute arbitrage here
    function uniswapV2Call(
        address sender,
        uint256 amount0,
        uint256 amount1,
        bytes calldata data
    ) external override {
        // Decode profit token from data
        address profitToken = abi.decode(data, (address));

        // Identify the borrowed token
        address token0 = IUniswapV2Pair(msg.sender).token0();
        address token1 = IUniswapV2Pair(msg.sender).token1();

        address flashToken = amount0 > 0 ? token0 : token1;
        uint256 flashAmount = amount0 > 0 ? amount0 : amount1;

        // Step 1: Arbitrage on SushiSwap
        IERC20(flashToken).approve(address(sushiRouter), flashAmount);
        address[] memory path = new address[](2);
        path[0] = flashToken;
        path[1] = profitToken;
        uint256 profitAmount = sushiRouter.swapExactTokensForTokens(
            flashAmount, 0, path, address(this), block.timestamp
        )[1];

        // Step 2: Calculate repay amount: flashAmount + 0.3% fee
        uint256 repayAmount = flashAmount + (flashAmount * 3) / 997;

        // Step 3: Buy back enough flashToken to repay
        IERC20(profitToken).approve(address(sushiRouter), profitAmount);
        path[0] = profitToken;
        path[1] = flashToken;
        uint256 flashTokenReceived = sushiRouter.swapExactTokensForTokens(
            profitAmount, repayAmount, path, address(this), block.timestamp
        )[1];

        require(flashTokenReceived >= repayAmount, "insufficient to repay");

        // Step 4: Repay the flash loan pair
        IERC20(flashToken).transfer(msg.sender, repayAmount);

        // Remaining profit (in profitToken) stays in this contract
    }
}
安全考虑
  • uniswapV2Call 中的 msg.sender 是 pair 合约地址，需要验证 pair 是合法的 UniswapV2 pair
  • Flash swap 本身就是重入，利用重入获得借出资产。需小心不要被外部二次重入攻击
  • gas 估算：两次 swap + 一次 transfer 约 200k-400k gas

我在准备 DeFi Agent 开发的过程中，用 Solidity + Foundry 实现了一个 DEX 三角套利 + 闪电贷套利系统。整个项目分为两个部分：第一，TriangularArbitrage 合约，实现 USDC → WETH → DAI → USDC 的多跳套利，核心是调用 UniswapV2 Router 的 swapExactTokensForTokens 完成路径交换；第二，FlashSwapArbitrage 合约，利用 UniswapV2 的闪电兑换（flash swap）在无本金的情况下借出大额资产，跨 DEX（Uniswap → SushiSwap）套利后归还。测试方面，我使用 Foundry 的 fork 测试模式，复制主网状态来验证套利逻辑，避免了在主网真实部署的高成本。这个项目让我深入理解了 AMM 恒定乘积机制、闪电贷的原子性保证、以及 Solidity 的 gas 优化技巧。后续我计划把链上数据读取封装为 MCP tool，让 AI agent 能自动发现套利机会。

面试追问预案
  • Q: 闪电贷的 atomic 性怎么保证？ A: 闪电贷借和还是在同一个交易内完成。如果套利失败、还不上钱，整个交易 revert，pair 资产不受损失。这是 EVM 的原子性保证的。
  • Q: 你怎么防止 sandwich attack？ A: 在 swap 时传入 amountOutMin 参数（滑点保护），并在链下用 getAmountsOut 预计算最小接收量。同时可以设置 deadline 防止交易被延迟执行。
  • Q: Foundry 和 Hardhat 你选哪个？为什么？ A: 我选 Foundry，因为纯 Solidity 测试比 JavaScript 测试更快、类型更安全，且 forge 的 fuzz 测试和 fork 测试非常强大。Hardhat 的生态更成熟，但 Foundry 的开发者体验更好。

十二、检索练习

不看上方内容，凭记忆回答。答错不扣分，只是帮你定位记忆空白。

1. Uniswap V2 的 swap() 函数执行完成后，pair 合约如何确保你归还了资产？

pair 在回调后检查 reserve0 * reserve1 >= k。你的还款加了 0.3% fee，乘积一定变大。这是 AMM 的核心安全机制：恒定乘积必须保持或增加。

2. TriangularArbitrage.execute() 合约中使用 amountOutMin = 0 有什么风险？如何修复？

amountOutMin = 0 意味着接受任何价格的 swap，攻击者可以通过 sandwich attack 让你以极差的价格成交。修复方法：在 swap 前调用 getAmountsOut 计算预期输出，设置合理的 slippage tolerance（如 0.5%）。

3. Foundry 中 vm.assume() 和 vm.expectRevert() 各有什么用途？

vm.assume(condition) 在 fuzz 测试中用于跳过不满足条件的输入（如假设输入大于 0）。vm.expectRevert(expectedError) 用于断言下一笔合约调用会 revert，常用来测试 require 条件。

4. 闪电贷合约的 uniswapV2Call 回调中，如何防止被非预期外部合约调用？

uniswapV2Call 是公开函数，任何人都可以调用。必须在函数开头验证 msg.sender 是合法的 UniswapV2 pair 地址（通过硬编码白名单或验证 pair.factory() 返回正确的 factory 地址）。

5. 为什么闪电贷合约中用完 flashAmount 买了 profitToken，还要再花钱买回 flashToken 还回去？能不能直接拿借来的 flashToken 套利后只把利润抽走？

因为你借的是 flashToken，还的必须是 flashToken（加 0.3% 手续费）。你不能凭空多出 flashToken，所以必须套利获利后用利润的一部分买回 flashToken 归还，剩下的才是净盈利。整个过程中 profitToken 作为中间锚定资产。
