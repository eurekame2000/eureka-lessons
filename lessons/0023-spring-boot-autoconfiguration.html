一、自动配置原理

1.1 @EnableAutoConfiguration 注解

@EnableAutoConfiguration 是 Spring Boot 自动配置的入口注解，它通过 @Import 导入 AutoConfigurationImportSelector。

@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Inherited
@AutoConfigurationPackage
@Import(AutoConfigurationImportSelector.class)
public interface EnableAutoConfiguration {
    String ENABLED_OVERRIDE_PROPERTY = "spring.boot.enableautoconfiguration";
    Class<?>[] exclude() default {};
    String[] excludeName() default {};
}
心智模型 @EnableAutoConfiguration = "启用自动配置"的开关。它通过 @Import 机制，让 AutoConfigurationImportSelector 去 classpath 扫描所有符合条件的配置类并注册到 IoC 容器。

1.3 spring.factories 文件

Spring Boot 2.x 和 3.x 的配置文件位置不同：

Spring Boot 2.x

META-INF/spring.factories:
org.springframework.boot.autoconfigure.EnableAutoConfiguration=\
com.example.XXXAutoConfiguration

Spring Boot 3.x

META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports:
com.example.XXXAutoConfiguration
重要变更 Spring Boot 3.x 废弃了 spring.factories 机制，改用 imports 文件。如果你维护的 starter 需要兼容两个版本，需注意这个差异。

1.4 @Conditional 条件注解家族

Spring Boot 提供了一系列 @Conditional 派生注解，用于条件化配置：

注解 条件 使用场景
@ConditionalOnClass 类路径存在某个类 依赖某个库时才启用配置
@ConditionalOnBean 容器中存在某个 Bean 依赖某个 Bean 时才启用配置
@ConditionalOnProperty 配置属性满足条件 根据配置文件动态启用
@ConditionalOnMissingBean 容器中不存在某个 Bean 允许用户自定义 Bean 覆盖默认

二、源码分析

2.1 AutoConfigurationImportSelector 源码

AutoConfigurationImportSelector 是实现自动配置的核心类，它实现了 DeferredImportSelector 接口。

public class AutoConfigurationImportSelector
    implements DeferredImportSelector, BeanClassLoaderAware,
    ResourceLoaderAware, BeanFactoryAware, EnvironmentAware {

    @Override
    public String[] selectImports(AnnotationMetadata annotationMetadata) {
        if (!isEnabled(annotationMetadata)) {
            return NO_IMPORTS;
        }
        // 获取自动配置入口
        AutoConfigurationEntry autoConfigurationEntry =
            getAutoConfigurationEntry(annotationMetadata);
        return StringUtils.toStringArray(
            autoConfigurationEntry.getConfigurations());
    }

    protected AutoConfigurationEntry getAutoConfigurationEntry(
            AnnotationMetadata annotationMetadata) {
        // 1. 获取候选配置类
        List<String> configurations = getCandidateConfigurations(...);
        // 2. 去重
        configurations = removeDuplicates(configurations);
        // 3. 过滤排除项
        Set<String> exclusions = getExclusions(...);
        configurations.removeAll(exclusions);
        // 4. 过滤条件注解
        configurations = filter(configurations, autoConfigurationMetadata);
        return new AutoConfigurationEntry(configurations, exclusions);
    }
}
源码要点 selectImports() 是入口方法，它调用 getAutoConfigurationEntry() 获取所有需要导入的配置类。核心步骤：获取候选配置 → 去重 → 排除 → 条件过滤。

2.2 与 spring-ai-mcp-server 的集成

分析 McpServerAutoConfiguration 源码，理解其自动配置机制：

@Configuration
@ConditionalOnClass(McpServer.class)
@EnableConfigurationProperties(McpServerProperties.class)
public class McpServerAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean
    public McpServer mcpServer(McpServerProperties properties) {
        return new McpServer(properties);
    }
}

这个配置类的三个关键注解：

  • @ConditionalOnClass(McpServer.class)：仅在类路径存在 McpServer 类时生效
  • @EnableConfigurationProperties：启用属性绑定
  • @ConditionalOnMissingBean：允许用户自定义 McpServer Bean 覆盖默认

三、实战演练：手写 ClickHouseMcpAutoConfiguration

3.1 自动配置类实现

现在来实现 clickhouse-mcp-server 的自动配置类：

@Configuration
@ConditionalOnClass(ClickHouseClient.class)
@EnableConfigurationProperties(ClickHouseMcpProperties.class)
public class ClickHouseMcpAutoConfiguration {

    private final ClickHouseMcpProperties properties;

    public ClickHouseMcpAutoConfiguration(
            ClickHouseMcpProperties properties) {
        this.properties = properties;
    }

    @Bean
    @ConditionalOnMissingBean
    public ClickHouseClient clickHouseClient() {
        return ClickHouseClient.builder()
            .host(properties.getHost())
            .port(properties.getPort())
            .database(properties.getDatabase())
            .build();
    }

    @Bean
    @ConditionalOnBean(ClickHouseClient.class)
    public ToolExecutor queryToolExecutor(
            ClickHouseClient client) {
        return new QueryToolExecutor(client);
    }
}
设计亮点 1. @ConditionalOnClass 确保仅在 ClickHouse 驱动存在时生效
2. @ConditionalOnMissingBean 允许用户自定义 ClickHouseClient
3. @ConditionalOnBean 确保仅当 ClickHouseClient 存在时才创建 ToolExecutor

四、面试话术

高频问题 1：讲讲 Spring Boot 自动配置原理？

标准答法（90秒版本）：

Spring Boot 自动配置原理可以分为五个步骤：

第一步，入口注解。@SpringBootApplication 包含了 @EnableAutoConfiguration，这个注解通过 @Import(AutoConfigurationImportSelector.class) 导入自动配置选择器。

第二步，配置加载。AutoConfigurationImportSelector 的 selectImports() 方法调用 SpringFactoriesLoader.loadFactoryNames()，读取 classpath 下所有 META-INF/spring.factories 文件（Spring Boot 2.x）或 META-INF/spring/*.imports 文件（Spring Boot 3.x）。

第三步，候选配置。这些文件中以 org.springframework.boot.autoconfigure.EnableAutoConfiguration 为 key 的配置类全限定名列表，就是候选的自动配置类。

第四步，条件过滤。Spring Boot 会对这些候选配置类进行条件过滤，检查 @Conditional 系列注解：@ConditionalOnClass（类路径检查）、@ConditionalOnBean（Bean 存在检查）、@ConditionalOnProperty（配置属性检查）等。不符合条件的配置类会被过滤掉。

第五步，注册 Bean。符合条件的配置类被注册到 IoC 容器，其中的 @Bean 方法返回的实例被注册为 Bean。

项目实战中，我在 clickhouse-mcp-server 项目中实现了 ClickHouseMcpAutoConfiguration，使用 @ConditionalOnClass(ClickHouseClient.class) 确保仅在 ClickHouse 驱动存在时生效，使用 @ConditionalOnMissingBean 允许用户自定义配置。

高频问题 2：@ConditionalOnBean 和 @ConditionalOnClass 的区别？

标准答法（60秒版本）：

这两个注解的核心区别在于检查的对象不同：

@ConditionalOnClass 检查的是类路径是否存在某个类。它只需要这个类在 classpath 中，不需要这个类被注册为 Bean。使用场景是：当某个依赖库存在时才启用配置。比如，仅当 ClickHouse JDBC 驱动在 classpath 中时，才启用 ClickHouse 相关的自动配置。

@ConditionalOnBean 检查的是IoC 容器中是否存在某个 Bean。它需要这个类已经被注册为 Bean。使用场景是：当某个 Bean 存在时才启用配置。比如，仅当容器中已经存在 DataSource Bean 时，才创建依赖 DataSource 的其他 Bean。

使用建议：优先使用 @ConditionalOnClass，因为它是编译时检查，更安全。谨慎使用 @ConditionalOnBean，因为它是运行时检查，可能会有 Bean 加载顺序的问题。在实际项目中，我通常组合使用：先用 @ConditionalOnClass 检查依赖库，再用 @ConditionalOnBean 检查依赖 Bean。

面试陷阱：自动配置类没有被加载 可能的原因：1) spring.factories 或 imports 文件配置错误；2) @Conditional 条件不满足；3) 被 exclude 排除；4) 自动配置类所在的包没有被扫描到。排查方法：开启 debug 日志，查看 AutoConfigurationReport。

五、章末 Quiz

不看上方内容，凭记忆回答。答错不扣分，只是帮你定位记忆空白。

1. @EnableAutoConfiguration 通过哪个注解导入自动配置选择器？

@EnableAutoConfiguration 通过 @Import(AutoConfigurationImportSelector.class) 导入自动配置选择器。@Import 是 Spring 的注解，用于导入配置类或 ImportSelector 实现。

2. Spring Boot 3.x 的自动配置文件路径是？

Spring Boot 3.x 废弃了 spring.factories 机制，改用 META-INF/spring/*.imports 文件。这个变更是为了提升启动性能，避免解析所有 spring.factories 文件。

3. @ConditionalOnBean 和 @ConditionalOnClass 的核心区别？

@ConditionalOnBean 检查 IoC 容器中是否存在某个 Bean，@ConditionalOnClass 检查类路径是否存在某个类。这是最容易被混淆的两个注解，面试中经常被问到。

4. AutoConfigurationImportSelector 的哪个方法返回要导入的配置类数组？

selectImports() 是 DeferredImportSelector 接口的方法，它返回要导入的配置类数组。内部调用 getAutoConfigurationEntry() 获取自动配置入口，然后转换为字符串数组。

5. 如何让 ClickHouseMcpAutoConfiguration 仅在 clickhouse.jdbc 驱动存在时生效？

@ConditionalOnClass(ClickHouseDriver.class) 会在类路径存在 ClickHouse 驱动类时才生效。这是实现"可选依赖"的标准做法，确保 starter 不会在缺少依赖时强制加载。
