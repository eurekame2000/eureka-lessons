一、IoC容器体系

1.1 BeanFactory 体系结构

BeanFactory 是 Spring IoC 容器的顶层接口，定义了获取 Bean 的基本规范。

// BeanFactory 核心接口
public interface BeanFactory {
    // 获取Bean
    Object getBean(String name) throws BeansException;

    // 判断是否包含Bean
    boolean containsBean(String name);

    // 判断Bean的作用域
    boolean isSingleton(String name) throws NoSuchBeanDefinitionException;
    boolean isPrototype(String name) throws NoSuchBeanDefinitionException;
}

BeanFactory 的继承体系：

BeanFactory (顶层接口)
    ↓
ListableBeanFactory (可列举Bean)
    ↓
ConfigurableBeanFactory (可配置)
    ↓
DefaultListableBeanFactory (核心实现类)
关键实现类：DefaultListableBeanFactory 这是 Spring 中最核心的 BeanFactory 实现，包含了完整的 Bean 定义注册、Bean 实例化、依赖注入等能力。ApplicationContext 内部就是持有一个 DefaultListableBeanFactory 实例。

1.2 ApplicationContext 体系

ApplicationContext 是 BeanFactory 的超集，提供了更多企业级功能。

// ApplicationContext 核心接口
public interface ApplicationContext extends
        EnvironmentCapable,      // 环境配置
        ListableBeanFactory,     // Bean列举
        HierarchicalBeanFactory, // 层级BeanFactory
        MessageSource,           // 国际化
        ApplicationEventPublisher, // 事件发布
        ResourcePatternResolver {  // 资源加载

    // 获取应用名称
    String getApplicationName();

    // 获取启动时间
    long getStartupDate();
}

ApplicationContext 的常见实现：

实现类 使用场景 配置方式
ClassPathXmlApplicationContext XML 配置 classpath 下的 XML 文件
FileSystemXmlApplicationContext XML 配置 文件系统中的 XML 文件
AnnotationConfigApplicationContext 注解配置 @Configuration 类
AnnotationConfigWebApplicationContext Web 环境 Web 应用注解配置

1.3 BeanFactory vs ApplicationContext

两者核心区别对比：

特性 BeanFactory ApplicationContext
初始化时机 懒加载（getBean 时才创建） 预加载（启动时创建所有非懒加载单例）
国际化支持 ❌ ✅ （MessageSource）
事件发布 ❌ ✅ （ApplicationEventPublisher）
资源加载 ❌ ✅ （ResourcePatternResolver）
自动配置 ❌ ✅ （@EnableAutoConfiguration）
BeanPostProcessor 注册 手动注册 自动注册
面试要点 实际开发中几乎不使用 BeanFactory，而是直接使用 ApplicationContext。Spring Boot 内部使用的是 AnnotationConfigServletWebServerApplicationContext。

二、ApplicationContext 初始化流程

ApplicationContext 初始化的核心是 refresh() 方法，这是 Spring 容器启动的入口。

2.1 refresh() 方法核心流程

public void refresh() throws BeansException, IllegalStateException {
    synchronized (this.startupShutdownMonitor) {
        // 1. 准备刷新
        prepareRefresh();

        // 2. 创建 BeanFactory 并加载 BeanDefinition
        ConfigurableListableBeanFactory beanFactory = obtainFreshBeanFactory();

        // 3. 准备 BeanFactory
        prepareBeanFactory(beanFactory);

        // 4. 后置处理 BeanFactory (留给子类扩展)
        postProcessBeanFactory(beanFactory);

        // 5. 执行 BeanFactoryPostProcessor
        invokeBeanFactoryPostProcessors(beanFactory);

        // 6. 注册 BeanPostProcessor
        registerBeanPostProcessors(beanFactory);

        // 7. 初始化 MessageSource（国际化）
        initMessageSource();

        // 8. 初始化事件广播器
        initApplicationEventMulticaster();

        // 9. 初始化其他特殊 Bean (留给子类扩展)
        onRefresh();

        // 10. 注册监听器
        registerListeners();

        // 11. 完成所有非懒加载 Bean 的初始化 ⭐
        finishBeanFactoryInitialization(beanFactory);

        // 12. 完成刷新
        finishRefresh();
    }
}
Phase 1: 准备阶段
prepareRefresh() — 设置启动时间、验证必填属性
obtainFreshBeanFactory() — 创建 DefaultListableBeanFactory，加载 BeanDefinition
Phase 2: BeanFactory 准备
prepareBeanFactory() — 设置 ClassLoader、注册默认 BeanPostProcessor
postProcessBeanFactory() — 子类扩展点（如 Spring Boot Servlet 容器）
Phase 3: BeanFactoryPostProcessor 执行
invokeBeanFactoryPostProcessors() — 执行所有的 BeanFactoryPostProcessor
├─ ConfigurationClassPostProcessor — 处理 @Configuration、@Bean
└─ PropertySourcesPlaceholderConfigurer — 处理 ${...} 占位符
Phase 4: BeanPostProcessor 注册
registerBeanPostProcessors() — 注册所有的 BeanPostProcessor
├─ AutowiredAnnotationBeanPostProcessor — 处理 @Autowired
└─ CommonAnnotationBeanPostProcessor — 处理 @PostConstruct、@PreDestroy
Phase 5: 其他组件初始化
initMessageSource() — 初始化国际化组件
initApplicationEventMulticaster() — 初始化事件广播器
onRefresh() — 子类扩展点（如 Spring Boot 启动 Web 服务器）
registerListeners() — 注册 ApplicationListener
Phase 6: Bean 实例化 ⭐
finishBeanFactoryInitialization() — 实例化所有非懒加载单例 Bean
Phase 7: 完成
finishRefresh() — 发布 ContextRefreshedEvent、启动 Lifecycle Processor

2.2 finishBeanFactoryInitialization() 详解

这是容器初始化的核心步骤，负责将所有非懒加载的单例 Bean 实例化。

protected void finishBeanFactoryInitialization(ConfigurableListableBeanFactory beanFactory) {
    // 初始化 ConversionService（类型转换服务）
    if (beanFactory.containsBean(CONVERSION_SERVICE_BEAN_NAME)) {
        beanFactory.getBean(CONVERSION_SERVICE_BEAN_NAME, ConversionService.class);
    }

    // 冻结 BeanDefinition（不允许再修改）
    beanFactory.freezeConfiguration();

    // ⭐ 核心：实例化所有非懒加载的单例 Bean
    beanFactory.preInstantiateSingletons();
}

// DefaultListableBeanFactory.preInstantiateSingletons()
public void preInstantiateSingletons() throws BeansException {
    // 遍历所有 BeanDefinition
    List<String> beanNames = new ArrayList<>(this.beanDefinitionNames);

    for (String beanName : beanNames) {
        RootBeanDefinition bd = getMergedLocalBeanDefinition(beanName);

        // 只实例化：非抽象 && 非懒加载 && 单例
        if (!bd.isAbstract() && bd.isSingleton() && !bd.isLazyInit()) {
            if (isFactoryBean(beanName)) {
                // FactoryBean 特殊处理
                getBean(FACTORY_BEAN_PREFIX + beanName);
            } else {
                // ⭐ 核心：获取 Bean（会触发创建）
                getBean(beanName);
            }
        }
    }
}

检验：finishBeanFactoryInitialization() 会实例化哪些 Bean？

❌ 懒加载的 Bean 不会被实例化
❌ prototype Bean 每次获取时才会创建
✅ 正确！只实例化非抽象、非懒加载、单例的 Bean
❌ 懒加载的 Bean 在 getBean 时才创建

三、Bean生命周期

Bean 从创建到销毁经历多个阶段，理解这些阶段对编写正确的 Spring 组件至关重要。

3.1 完整生命周期流程图

阶段 1: 实例化（Instantiation）
createBeanInstance() — 通过构造器反射创建对象
├─ 如果有无参构造器：直接反射创建
└─ 如果有带参构造器：解析依赖，先创建依赖 Bean
阶段 2: 属性注入（Population）
populateBean() — 注入依赖的属性
├─ @Autowired 注入
├─ @Value 注入
└─ setter 方法注入（XML 配置）
阶段 3: 初始化（Initialization）⭐
3.1 Aware 接口回调
├─ BeanNameAware.setBeanName()
├─ BeanFactoryAware.setBeanFactory()
└─ ApplicationContextAware.setApplicationContext()
3.2 BeanPostProcessor 前置处理
└─ postProcessBeforeInitialization()
3.3 初始化方法调用
├─ @PostConstruct 标注的方法
├─ InitializingBean.afterPropertiesSet()
└─ 自定义 init-method
3.4 BeanPostProcessor 后置处理 ⭐
└─ postProcessAfterInitialization() — AOP 代理在此创建
阶段 4: 使用（In Use）
Bean 就绪，可被应用使用
阶段 5: 销毁（Destruction）
5.1 @PreDestroy 标注的方法
5.2 DisposableBean.destroy()
5.3 自定义 destroy-method

3.2 生命周期回调接口详解

import org.springframework.beans.factory.*;
import org.springframework.context.*;
import javax.annotation.*;

@Component
public class MyBean implements
        BeanNameAware,
        BeanFactoryAware,
        ApplicationContextAware,
        InitializingBean,
        DisposableBean {

    private String beanName;
    private BeanFactory beanFactory;
    private ApplicationContext applicationContext;

    // 1. Aware 接口回调
    @Override
    public void setBeanName(String name) {
        this.beanName = name;
        System.out.println("1. BeanNameAware: " + name);
    }

    @Override
    public void setBeanFactory(BeanFactory beanFactory) {
        this.beanFactory = beanFactory;
        System.out.println("2. BeanFactoryAware");
    }

    @Override
    public void setApplicationContext(ApplicationContext applicationContext) {
        this.applicationContext = applicationContext;
        System.out.println("3. ApplicationContextAware");
    }

    // 2. @PostConstruct
    @PostConstruct
    public void init() {
        System.out.println("4. @PostConstruct");
    }

    // 3. InitializingBean
    @Override
    public void afterPropertiesSet() throws Exception {
        System.out.println("5. InitializingBean.afterPropertiesSet()");
    }

    // 4. @PreDestroy
    @PreDestroy
    public void cleanup() {
        System.out.println("6. @PreDestroy");
    }

    // 5. DisposableBean
    @Override
    public void destroy() throws Exception {
        System.out.println("7. DisposableBean.destroy()");
    }
}

执行顺序输出：

1. BeanNameAware: myBean
2. BeanFactoryAware
3. ApplicationContextAware
4. @PostConstruct
5. InitializingBean.afterPropertiesSet()
6. @PreDestroy  (容器关闭时)
7. DisposableBean.destroy()  (容器关闭时)
注意：@PostConstruct vs InitializingBean @PostConstruct 是 JSR-250 标准注解，不依赖 Spring 接口，耦合度更低。InitializingBean 是 Spring 接口，但执行时机稍晚于 @PostConstruct。实际开发中推荐使用 @PostConstruct。

3.3 BeanPostProcessor 的作用

BeanPostProcessor 是 Spring 生命周期中最强大的扩展点，允许在 Bean 初始化前后进行自定义处理。

public interface BeanPostProcessor {

    // 初始化前调用
    @Nullable
    default Object postProcessBeforeInitialization(Object bean, String beanName)
            throws BeansException {
        return bean;
    }

    // 初始化后调用 ⭐ AOP 代理在此创建
    @Nullable
    default Object postProcessAfterInitialization(Object bean, String beanName)
            throws BeansException {
        return bean;
    }
}

常见的 BeanPostProcessor 实现：

BeanPostProcessor 作用
AutowiredAnnotationBeanPostProcessor 处理 @Autowired、@Value 注入
CommonAnnotationBeanPostProcessor 处理 @PostConstruct、@PreDestroy、@Resource
AbstractAutoProxyCreator 创建 AOP 代理（@Transactional 等）
ApplicationContextAwareProcessor 触发 Aware 接口回调

检验：@Transactional 注解的 Bean 在生命周期哪个阶段变成代理对象？

❌ 这是初始化前的处理
✅ 正确！AOP 代理在初始化后通过 postProcessAfterInitialization 创建
❌ afterPropertiesSet 是初始化回调，不是代理创建时机
❌ Aware 回调在初始化前执行

四、循环依赖

循环依赖是指两个或多个 Bean 相互依赖，形成闭环。Spring 通过三级缓存机制解决部分循环依赖问题。

4.1 三级缓存机制

// DefaultSingletonBeanRegistry 中的三级缓存

// 一级缓存：完整 Bean（单例池）
private final Map<String, Object> singletonObjects = new ConcurrentHashMap<>(256);

// 二级缓存：早期 Bean（已实例化但未完成初始化）
private final Map<String, Object> earlySingletonObjects = new HashMap<>(16);

// 三级缓存：Bean 工厂（用于创建早期 Bean 的ObjectFactory）
private final Map<String, ObjectFactory<?>> singletonFactories = new HashMap<>(16);
三级缓存的作用
  • singletonObjects：存放完全初始化好的 Bean，供外部使用
  • earlySingletonObjects：存放早期的 Bean（已实例化但未初始化），用于解决循环依赖
  • singletonFactories：存放 Bean 的 ObjectFactory，可以生成早期 Bean（可能已经是代理对象）

4.2 循环依赖解决流程

以 A → B → A 的循环依赖为例：

步骤 1: 创建 Bean A
1.1 getBean("A") 被调用
1.2 从一级缓存查找 A → 未找到
1.3 实例化 A（调用构造器）
1.4 将 A 的 ObjectFactory 放入三级缓存（singletonFactories）
1.5 开始注入 A 的属性 → 发现需要 B
步骤 2: 创建 Bean B
2.1 getBean("B") 被调用
2.2 从一级缓存查找 B → 未找到
2.3 实例化 B（调用构造器）
2.4 将 B 的 ObjectFactory 放入三级缓存
2.5 开始注入 B 的属性 → 发现需要 A
2.6 从一级缓存查找 A → 未找到
2.7 从二级缓存查找 A → 未找到
2.8 从三级缓存查找 A → 找到！
2.9 调用 A 的 ObjectFactory.getObject() → 获取早期 A（可能是代理）
2.10 将 A 从三级缓存提升到二级缓存（earlySingletonObjects）
2.11 B 注入 A 成功（注入的是早期 A）
2.12 B 完成初始化 → 放入一级缓存（singletonObjects）
步骤 3: 完成 Bean A
3.1 A 注入 B 成功（B 已在一级缓存）
3.2 A 完成初始化
3.3 将 A 从二级缓存提升到一级缓存
3.4 清除 A 的二级缓存和三级缓存

4.3 循环依赖的限制

场景 能否解决 原因
属性注入循环依赖（@Autowired） ✅ 能 通过三级缓存机制解决
setter 注入循环依赖 ✅ 能 通过三级缓存机制解决
构造器循环依赖 ❌ 不能 无法实例化（构造器需要参数）
@Async 循环依赖 ❌ 不能 代理创建时机问题（需要额外配置）
prototype 循环依赖 ❌ 不能 非单例，不使用缓存
构造器循环依赖无法解决的原因 
@Component
public class A {
    private final B b;

    // 构造器需要 B，但 B 还未创建
    public A(B b) {
        this.b = b;
    }
}

@Component
public class B {
    private final A a;

    // 构造器需要 A，但 A 还未创建
    public B(A a) {
        this.a = a;
    }
}

// 报错：BeanCurrentlyInCreationException
// 原因：实例化 A 需要 B，实例化 B 需要 A，死循环

五、面试话术

面试场景 1：说说 Spring IoC 容器的初始化过程？

答：

Spring IoC 容器的初始化核心是 ApplicationContext.refresh() 方法，主要流程：

1. 准备阶段：
   - prepareRefresh()：设置启动时间、验证必填属性

2. 创建 BeanFactory：
   - obtainFreshBeanFactory()：创建 DefaultListableBeanFactory
   - 加载 BeanDefinition（XML 或注解）

3. BeanFactory 准备：
   - prepareBeanFactory()：设置 ClassLoader、注册默认 BeanPostProcessor
   - postProcessBeanFactory()：子类扩展点

4. 执行 BeanFactoryPostProcessor：
   - invokeBeanFactoryPostProcessors()
   - ConfigurationClassPostProcessor 处理 @Configuration、@Bean
   - PropertySourcesPlaceholderConfigurer 处理 ${...} 占位符

5. 注册 BeanPostProcessor：
   - registerBeanPostProcessors()
   - AutowiredAnnotationBeanPostProcessor（处理 @Autowired）
   - CommonAnnotationBeanPostProcessor（处理 @PostConstruct）

6. 实例化 Bean（核心）：
   - finishBeanFactoryInitialization()
   - preInstantiateSingletons()：实例化所有非懒加载单例 Bean
   - 对每个 Bean 调用 getBean()

7. 完成刷新：
   - finishRefresh()：发布 ContextRefreshedEvent
   - 启动 Lifecycle Processor
面试场景 2：Bean 的生命周期有哪些阶段？

答：

Bean 的生命周期分为五大阶段：

1. 实例化（Instantiation）：
   - 通过构造器反射创建对象

2. 属性注入（Population）：
   - @Autowired 注入依赖
   - @Value 注入配置
   - setter 方法注入（XML 配置）

3. 初始化（Initialization）：
   - Aware 接口回调（BeanNameAware、BeanFactoryAware）
   - BeanPostProcessor.postProcessBeforeInitialization()
   - @PostConstruct 标注的方法
   - InitializingBean.afterPropertiesSet()
   - 自定义 init-method
   - BeanPostProcessor.postProcessAfterInitialization()（AOP 代理在此创建）

4. 使用（In Use）：
   - Bean 就绪，可被应用使用

5. 销毁（Destruction）：
   - @PreDestroy 标注的方法
   - DisposableBean.destroy()
   - 自定义 destroy-method
面试场景 3：Spring 能解决所有循环依赖吗？为什么？

答：

不能，Spring 只能解决部分循环依赖，有限制：

✅ 可解决：
- 属性注入循环依赖（@Autowired、setter）
- 通过三级缓存机制解决

❌ 无法解决：
1. 构造器循环依赖：
   - 原因：无法实例化（构造器需要参数，参数未创建）
   - 报错：BeanCurrentlyInCreationException

2. @Async 循环依赖：
   - 原因：代理创建时机问题（@Async 的代理在初始化后创建）
   - 解决：使用 @Lazy 延迟注入

3. prototype 循环依赖：
   - 原因：prototype 作用域不使用缓存
   - 解决：使用代理或重构设计

三级缓存原理：
- singletonObjects（一级）：完整 Bean
- earlySingletonObjects（二级）：早期 Bean（半成品）
- singletonFactories（三级）：ObjectFactory（用于创建早期 Bean，可能已经是代理）

解决流程（A → B → A）：
1. 创建 A，实例化后放入三级缓存
2. 注入 A 的属性时发现需要 B，开始创建 B
3. B 注入属性时发现需要 A
4. 从三级缓存获取 A 的 ObjectFactory
5. 调用 getObject() 获取早期 A（可能是代理）
6. 将 A 提升到二级缓存
7. B 完成初始化，放入一级缓存
8. A 注入 B 成功，完成初始化
